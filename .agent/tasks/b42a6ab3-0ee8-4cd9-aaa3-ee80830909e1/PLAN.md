# План реализации next_delay

Статус: проект Architect; исполнение разрешает контроллер только после независимого Debate и решения владельца. PLAN.json — машиночитаемый источник шагов и AC. Предварительный план Triage заменён этим планом; TEAM.json остаётся историей оценки, не переопределяет его.

## S1 — точный расчёт с ограничением

- Файл: `retry_policy.py`.
- Зависимости: нет. Критерии: AC1, AC2, AC3, AC5.
- Сохранить существующую constant_delay без изменения тела/сигнатуры. Добавить только next_delay и при необходимости небольшой внутренний помощник для пары числитель/знаменатель; разрешён только стандартный math для isfinite.
- Сначала валидировать все аргументы. attempt: isinstance(int), исключить bool, >=0. Остальные: isinstance(int,float), исключить bool, конечность проверять только для float, знаки согласно R1. Ошибки всегда ValueError. remaining==0 вернуть None только после полной проверки остальных аргументов.
- Реализовать ровно D2–D3 SPEC: точные пары B/b и M/m; L=B*m, R=M*b; сравнить L.bit_length()+attempt с R.bit_length(). Большая длина означает cap, меньшая — ненасыщенный результат; при равенстве сравнить L<<attempt с R (>= означает cap). Никакого предварительного 2**attempt, cap/base или логарифма.
- При cap взять max_delay. Иначе k=b.bit_length()-1; attempt>=k даёт int B<<(attempt-k), иначе float B/(b>>attempt). Возвратить candidate при candidate<=remaining, иначе None. Не преобразовывать все числа в float. Допустимы численно равные int/float; не округлять.
- Инварианты: валидация завершена до раннего выхода; candidate>0 и <=max_delay; каждый сдвиг ограничен размерами входных чисел; нет глобального изменяемого состояния, I/O, времени, случайности или ожидания.
- Проверка во время Work: `python3 -m py_compile retry_policy.py`; после S2 — адресные unittest. Review проверяет обоснование ограниченности и чистоту по коду.

## S2 — адресные unittest

- Файл: новый `tests/test_retry_policy.py`.
- Зависимости: S1. Критерии: AC1, AC2, AC3, AC4.
- unittest.TestCase; subTest для независимых значений. Точные assertEqual/assertIsNone/assertRaises(ValueError); без допуска epsilon, проверки точного типа равных int/float и текста ошибок. Не переписывать tests/test_baseline.py и не дублировать его буквальное значение как новый контракт.
- Нормальные примеры `(attempt, base_delay, max_delay, remaining) -> result`:
  - `(0,1,10,10)->1`, `(3,0.25,10,10)->2`, `(4,1,10,10)->10`.
  - `(0,8,3,3)->3` (base больше cap), `(0,3,3,3)->3`, `(3,1,8,8)->8` (точный cap), `(1,0.25,0.5,0.5)->0.5`.
  - `(3,1,10,8)->8`, тот же случай с remaining=7 -> None; `(4,1,10,9)->None`; remaining=0 и -0.0 -> None при корректных остальных аргументах; remaining=0.5 против задержки 0.5 возвращает задержку, 0.49 даёт None.
- Недопустимые значения по отдельности для КАЖДОЙ позиции: True, False, None, строка, complex, список, float('nan'), float('inf'), -float('inf'). Для attempt дополнительно -1, 0.0, 1.5; для base_delay/max_delay: 0, 0.0, -0.0, -1, -0.5; для remaining: -1, -0.5. Остальные аргументы при подстановке корректны. Повторить невалидные attempt/base/max с remaining=0: ранний None не скрывает ошибки. Проверить допустимый attempt=0, положительные дроби, нулевой remaining и смесь int/float.
- Числовые крайности, вычисляемые только в тестах:
  - `H=10**400`: `(0,H,10*H,10*H)->H`, `(1,H,10*H,10*H)->2*H`; без OverflowError при проверке конечности.
  - `F=sys.float_info.max`: `(1,F,F,F)->F` без inf; `(1,F,1<<2000,1<<2000)->int(F)*2`.
  - `s=float.fromhex('0x0.0000000000001p-1022')`: `(0,s,1,s)->s`, `(1074,s,2,1)->1`, `(2098,s,F,F)->F`.
  - `(1500,1.0,1<<2000,1<<2000)->1<<1500` (допустимая задержка вне float-диапазона).
  - Граница рядом с cap: `(3,1.0,math.nextafter(8.0,0.0),8)->math.nextafter(8.0,0.0)`; `(3,1.0,math.nextafter(8.0,math.inf),8)->8`. Так различаются <, == и > без ошибок округления логарифмов.
- Huge-attempt тест запускает отдельный локальный интерпретатор через subprocess.run([sys.executable, '-c', ...], timeout=5, check=True, capture_output=True), с cwd корнем репозитория, определённым от __file__. В дочернем процессе обычные unittest-assertions (не отключаемые python -O) проверяют `(10**9,1,10,10)->10`, такой же случай с remaining=9 -> None, `(10**9,s,F,F)->F` и `(10**100,1,10,10)->10`. Timeout считается провалом и завершает дочерний процесс; это watchdog, а не SLA. Функция сама subprocess/часы не использует. Все прочие крайние случаи выполняются обычными тестами.
- Повторяемость: одинаковые валидные входы дают одинаковое значение несколько раз, включая вызов между ними с другими аргументами. Не вводить property-testing или сторонние пакеты.
- Проверка в Work: `python3 -m unittest discover -s tests -p test_retry_policy.py -v`. Это только новый файл; полный discovery агенты не запускают.

## Проверки, зависимости и границы ответственности

Существующая `.agent/project.json` уже содержит quick `python3 -m py_compile retry_policy.py` (timeout 30 s) и полный `python3 -m unittest discover -s tests -v` (timeout 60 s). Это реальные проверки исполняемого кода, не заглушки. Новое имя test_retry_policy.py автоматически попадает в discovery. Изменение check policy не требуется и запрещено: ROUTE.json без project_policy_change. CI также выполняет unittest discover; файлы CI не менять.

Новых пакетов и dependency install нет: только встроенные Python int/float и стандартная библиотека. На 2026-11-11 локально подтверждён Python 3.12.3 и документация __doc__ для используемых числовых API; внешних интеграций нет. Воспроизводимый setup зависимостей — чистый checkout, доступный Python и отсутствие pip install. Версию интерпретатора контроллер фиксирует через `python3 --version` в Verify/CI; точное совпадение окружения ubuntu-latest не гарантировано. Не объявлять произвольный диапазон поддерживаемых major/minor. Совместимость на фактическом runtime проверяют числовые случаи S2 (включая subnormal, крайний float и mixed int/float), а не только синтаксис. При их провале — блокер контроллеру без молчаливой смены CI или контракта.

После завершения Work контроллер выполняет отдельный полный Verify. Review читает request.checks для текущего HEAD; устаревшие результаты возвращаются контроллеру на Verify, не засчитываются. AC1–AC4 подтверждаются новым unittest-файлом; сохранение baseline — исходным тестом и diff; отсутствие побочных эффектов и ограниченность алгоритма — чтением кода. На этапе Spec приложение не тестировалось и не изменялось.

## Отказы, откат, согласование

Невалидные входы — ValueError без изменения состояния. Бюджет исчерпан — None; это нормальный результат, не ошибка. Миграции и восстановление данных отсутствуют. Если реализация нарушает контракт, сообщить блокер; Fix/новая попытка этим пилотом не разрешены. Откат продуктового commit выполняет только уполномоченный контроллер, сохраняя чужие изменения, без reset ветки и изменения политики; функция не имеет устойчивых побочных эффектов.

Дизайн, UAT/dev-preview и assets не нужны. ADR/project_knowledge отсутствуют, изменений знаний не планируется. Продуктовых вопросов нет. Нужны независимый Debate и согласование плана владельцем в Telegram, затем предусмотренная приёмка результата. Текущее request.route подтверждает Architect astra.xhigh, Builder deepseek, Reviewer sonnet.medium; слот оппонента текущим запросом не подтверждён (BRIEF требует OpenCode GO / DeepSeek), назначение остаётся контроллеру. Возражений оппонента в текущих входах нет; при их поступлении требуется адресный ответ на каждое в пределах разрешённой роли.
