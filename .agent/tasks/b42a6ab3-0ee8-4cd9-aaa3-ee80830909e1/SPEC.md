## Требования владельца

- **R1.** Добавить next_delay(attempt, base_delay, max_delay, remaining): attempt — int >= 0 без bool; остальные аргументы — конечные int/float без bool; base_delay и max_delay > 0, remaining >= 0. Любые некорректные аргументы дают ValueError.
- **R2.** Возвращать min(max_delay, base_delay * 2**attempt), если задержка <= remaining; точное равенство допустимо; при remaining == 0 или превышении бюджета возвращать None.
- **R3.** Чистый детерминированный расчёт: attempt=10**9 обрабатывается быстро, без огромной степени, переполнения и зависания; без внешних зависимостей, ожиданий, сети, часов и случайности.
- **R4.** Добавить адресные unittest для нормальных случаев, границ, точного/исчерпанного бюджета, bool, отрицательных/нечисловых/NaN/inf аргументов и огромного attempt; описать контракт в README.
- **R5.** Сохранить constant_delay и поведение вне задачи относительно baseline 067c6b554b31cd8929bc58bd4402ab3fcd5d9aae. Продуктовые изменения ограничены retry_policy.py, tests/test_retry_policy.py, README.md.

## Архитектурные решения

- **D1.** Сначала валидировать все четыре аргумента; bool отклонять отдельно; math.isfinite применять только к float, поскольку Python int конечен и не ограничен float-диапазоном.
- **D2.** Сравнивать точные положительные дроби int/float: int -> (x,1), float -> x.as_integer_ratio(). Для base B/b и cap M/m положить L=B*m, R=M*b. Сравнить L.bit_length()+attempt с R.bit_length(); сдвиг L<<attempt нужен только при равных длинах. Если результат >= cap, выбрать исходный max_delay.
- **D3.** При ненасыщенном результате attempt уже ограничен размерами входа. Для base B/b, b=2**k и k=b.bit_length()-1: если attempt>=k, получить int B<<(attempt-k); иначе получить float B/(b>>attempt). Вторая ветвь точно представима и конечна. Сравнить candidate<=remaining напрямую; вернуть candidate или None. После полной валидации remaining==0 возвращает None.
- **D4.** Возвращаемый числовой тип не фиксировать: равные int/float эквивалентны; целая задержка, превышающая float-диапазон, остаётся int. Не использовать округление, логарифмы, float-приведение int, 2**attempt или цикл длиной attempt.
- **D5.** Новые тесты только в tests/test_retry_policy.py; существующую constant_delay и baseline-тест не переписывать. README дополнить контрактом без удаления вводного текста.
- **D6.** Route standard; design.required=false; needs_uat=false. Проверки уже реальные, project_policy_change не требуется. Без пакетов, интеграций, миграций и изменений ADR.
- **D7.** Сначала независимый Debate и согласование плана владельцем в Telegram; затем Work в Docker, отдельный Verify, Review, Security, независимая приёмка в Telegram и публикация/merge только контроллером.

### Обоснование числового алгоритма

Для положительных L и R двоичная длина L*2**attempt равна L.bit_length()+attempt. Неравные длины сразу определяют порядок, поэтому при огромном attempt выбирается cap без построения степени. При равных длинах attempt ограничен R.bit_length(), и точное сравнение сдвигом не создаёт числа, превосходящего входные перекрёстные произведения по размеру. Равенство с cap выбирает cap. При ненасыщенном результате сдвиг также ограничен размерами входов; для int это точная целая арифметика.

У конечного float дробь B/b точна, b — степень двойки. Если после масштабирования знаменатель стал единицей, int сохраняет результат даже за пределами float. Иначе B/(b>>attempt) — точная двоичная дробь с не более чем исходным числом значащих бит; она конечна и представима. Прямое сравнение int/float с remaining сохраняет границу без epsilon. Работа зависит от размеров предоставленных чисел, а не от численного значения огромного attempt; не обещается постоянное время для входных int произвольного размера.

## Предположения и границы доказательств

- **A1.** Владелец задаёт числовое значение, а не точный тип ответа или сообщение ошибки. Разрешены равные int/float, ValueError проверяется по классу; округление не вводится. Это архитектурное уточнение, не требование отдавать всегда float.
- **A2.** Все встроенные int конечны, в том числе вне float-диапазона. Это следствие R1; необоснованного верхнего предела для int нет. bool отклоняется до isinstance(int). Не добавлять поддержку Decimal/Fraction/строк через неявное преобразование.
- **A3.** Источник версии — локальный `python3 --version`: 3.12.3 на 2026-11-11. Локальная документация float.as_integer_ratio, int.bit_length, math.isfinite проверена через __doc__. Новых библиотечных/API-интеграций, package metadata и pip setup нет. Внешние источники не требуются и не использованы. Совместимость с иными интерпретаторами не объявляется без проверки; существующий CI берёт python3 из ubuntu-latest.
- **A4.** request.route подтверждает astra.xhigh для Architect, deepseek для Builder и sonnet.medium для Reviewer. Назначение оппонента BRIEF — OpenCode GO / DeepSeek; фактический слот оппонента текущим request не подтверждён. Контроллер управляет назначением, агент модель не подменяет.

## Измеримые критерии

- **AC1 → R1.** Матрица недопустимых значений по каждой позиции даёт ValueError, в том числе при remaining=0; большие конечные int принимаются без преобразования во float. Корректные значения на границе допускаются. Проверка: `python3 -m unittest discover -s tests -p test_retry_policy.py -v`.
- **AC2 → R2.** Таблица S2 подтверждает экспоненциальный рост, cap (включая base_delay > max_delay), точный бюджет, бюджет ниже задержки и нулевой бюджет; результат сравнивается точно, без epsilon. Проверка: `python3 -m unittest discover -s tests -p test_retry_policy.py -v`.
- **AC3 → R3.** Адресные тесты подтверждают огромные attempt, subnormal/max-float и большие int; subprocess с huge-attempt вызовами завершается за watchdog 5 секунд. Review подтверждает ограничение сдвигов размерами входных чисел, отсутствие степени/цикла по attempt и побочных эффектов. Проверка: `python3 -m unittest discover -s tests -p test_retry_policy.py -v`.
- **AC4 → R4.** tests/test_retry_policy.py содержит матрицу S2 и тест повторяемости; README описывает все аргументы, ValueError, cap, равенство бюджета, None, примеры и адресную команду. Существующий Verify обнаруживает новые тесты. Проверка: `python3 -m unittest discover -s tests -p test_retry_policy.py -v`.
- **AC5 → R5.** quick проходит; diff к baseline сохраняет constant_delay и tests/test_baseline.py, все прочие продуктовые файлы неизменны. Review сверяет сохранённый полный Verify с HEAD. Проверка: `scripts/agent-check --phase quick`.

AC4 дополнительно проверяется чтением README и сопоставлением с R1–R3; AC5 — diff к именованному baseline и сохранённым Verify. Автоматический результат одной команды не заменяет эти проверки. Полная матрица и соответствие шагам определены PLAN.md/PLAN.json; новых неоговорённых требований к форматированию или типам результата нет.
