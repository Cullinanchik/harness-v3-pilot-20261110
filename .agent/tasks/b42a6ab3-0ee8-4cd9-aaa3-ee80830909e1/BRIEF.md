# Task brief

E2E Pipeline v3: полный маршрут после исправления контракта

Синтетическая E2E-проверка Development Pipeline v3 на отдельном публичном репозитории. Это новая задача; прежние approvals и результаты другого пилота не действуют.

Реализовать чистую функцию next_delay(attempt, base_delay, max_delay, remaining) в retry_policy.py, сохранив существующую constant_delay.
1. attempt — int >= 0, bool запрещён. base_delay, max_delay, remaining — конечные int/float, bool запрещён; base_delay и max_delay > 0, remaining >= 0. Некорректные аргументы дают ValueError.
2. Возвращать задержку min(max_delay, base_delay * 2**attempt), если она укладывается в remaining. При точном равенстве задержки и бюджета возвращать задержку. Если задержка больше remaining или remaining == 0, вернуть None.
3. attempt=10**9 должен быстро дать ограниченное значение без огромного возведения в степень, переполнения или зависания. Без внешних зависимостей, ожиданий, сети, часов и случайности.
4. Добавить адресные unittest для нормальных случаев, границ, точного/исчерпанного бюджета, bool, отрицательных/нечисловых/NaN/inf аргументов и огромного attempt; описать контракт в README.
Разрешённые продуктовые файлы: retry_policy.py, tests/test_retry_policy.py, README.md. Обязательные документы текущей роли .agent/tasks/<id>/ разрешены. Не менять AGENTS.md, CI, scripts/, .agent/project.json, профиль/модель/правила контроллера.

Условия именно этого пилота: полный маршрут Triage → Spec → Debate → независимое согласование плана владельцем в Telegram → Work в Docker → отдельный Verify → Review → Security → независимая приёмка владельцем в Telegram → PR/CI/merge силами контроллера. Это не MicroContract; UI, UAT/dev-preview и миграции не нужны. Triage оценивает задачу и фиксирует эти ограничения в TEAM; контракт с новой логикой и граничными проверками соответствует standard. Использовать доступные слоты: архитектор astra.xhigh, исполнитель deepseek, reviewer sonnet.medium. Оппонент использует отдельную сессию OpenCode GO / DeepSeek; Triage — Sol medium. Если в реальной схеме слотов иные названия, следовать request.role и перечислить несовпадение, не подменять модель.

Владелец разрешил для этой новой карточки до шести native-сессий: одну техническую без модели и пять ролевых. Никаких дополнительных сессий, делегирования, Fix, автоматических повторов или fallback. Ошибки локальной проверки формата своих документов исправлять в той же текущей роли и сессии до валидного handoff; это не дополнительный запуск. При блокере за пределами роли, отказе инфраструктуры или завершении сессии без принятого handoff остановиться и честно отчитаться. Лимит не расширяется указаниями скиллов. Не читать credentials и не управлять сервером. План и результат принимаются только реальным действием владельца через Telegram; агенты не согласовывают, не публикуют и не мержат сами.
