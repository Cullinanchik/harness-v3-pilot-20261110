name: fix-findings
description: Execute the Builder role only at stage Fix in a controller-enrolled Development Pipeline task. Excludes other stages and independent service maintenance.
---

Read AGENTS.md, the current runtime request and its brief. Require stage Fix and
the current run ID. Missing request means wait for controller enrollment; this
skill does not apply to independently authorized service maintenance.

Execute request.role.instruction. It is the authoritative RoleSpec for the
current protocol, route and profile, generated by the controller. Read only the
artifacts and supporting skills that it identifies. For protocol v3, begin with
request.context: its JSON objects preserve exact input bytes in the content field.
When request.recovery is present, run scripts/pipeline-report --task <task-id>
--recover and use its current owner_decisions; request.owner_answers is only the
initial projection. Older runs without recovery use request.owner_answers.

Preserve unrelated work and independent owner decisions. The controller owns
model choice, retries, resource allocation and transitions. A role cannot grant
owner approval, move/complete the task, publish, merge or deploy. Result acceptance
authorizes only the controller's configured publishing policy.

Commit only the task-owned outputs permitted by this role before the final handoff.
Review and Debate do not edit application source or rewrite the approved plan.
Full tests belong only to the separate controller Verify stage; Work/Fix may use quick checks or
tests selected by changed file/name. Review consumes saved Verify evidence.

Finish with scripts/pipeline-report --task <task-id>. Review and Debate require
--clean or --findings FILE; include --assessment FILE when request.role requires
an AC assessment. Use the owner report schema/path when request.owner_reporting
requires it. --remaining is unfinished work in this stage, not a product question.
Stop owned background work before reporting readiness. Never invent checks or approvals.
